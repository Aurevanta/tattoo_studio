# Task: The tattooer's package — a link to a design (audit 2026-10-08 UX-05, ADR-0032)

## 1. Problem / requested change

The audit of 2026-10-08 (UX-05): no way to share a design with the tattooer; only loose downloads.
The owner: "continua con portada publica y paquete para el tatuador". Evidence: INTENT.

## 2. Current behavior

Every design was private to its account; the result offered PDF/SVG/PNG downloads only, without the
measurements, zone, style or description beside them. Evidence: OBSERVED (no share route in
`apps/web/src/app/api`, none in the worker).

## 3. Requirements

- **REQ-001** — Contract `shared-design` (both runtimes): the design, stencils and PDFs, size,
  zone and side, style, colour mode and palette, the idea, the professional description, the
  stencil method, `reviewRequired: true`; no body type, account, capture or background; the skin
  view only when composed on generated skin (else null).
- **REQ-002** — The worker creates a link for a finished design of the calling account (random
  token, only its SHA-256 stored, 30 days, at most 20 open per account), reports how many are open
  for a design, closes them all on request, and forgets them on erasure. Opening a link needs the
  service token and the token in `X-Share-Token`; it rebuilds the view from the stored job,
  validates it, and serves only that view's files.
- **REQ-003** — The web: `POST/GET/DELETE /api/shares` (account; creating needs the current
  consent) and the public page `/t/<token>` (outside the page gate, `noindex`, no referrer) with
  the sheet, images, print button and downloads; `/api/shared/<token>/<asset>` serves files inert
  (`sandbox` CSP). An unavailable link answers 404 with a plain Spanish message.
- **REQ-004** — In the result, «Para tu tatuador» says what the link shows and that body photos are
  never part of it, creates it, copies or sends it, shows its end date, and withdraws it; on a
  later visit it says a link is open and can withdraw it.
- **REQ-005** — The privacy policy names sharing and its 30 days; `IMAGES_VERSION` is bumped.

## 4. Acceptance criteria

- **AC-001** — Contract corpora: 6 valid and 16 invalid `shared-design` fixtures (body type,
  account, capture, background, review false, pixels, bad ids/mime/timestamp/vocabulary, empty
  idea, missing stencil and expiry) agree in TypeScript and Python.
- **AC-002** — `app/tests/test_shares.py`: the view validates and holds what the brief says, its
  six files open and another file of the account does not; on an own photo the skin view is null
  and the composite and background do not open; only the owner shares, only the service opens,
  wrong tokens 404; withdrawal and erasure close links; open-links count; the ledger keeps a
  digest, expires and limits.
- **AC-003** — Web: `api/shares/route.test.ts` (owner header, path answer, consent 428, bad id
  400, status, delete; file route passes the token in a header not the path, no owner, `sandbox`;
  impossible token or file never reaches the worker; closed link 404), `SharedDesignView.test.tsx`
  (Spanish sheet, downloads, review note, no skin view on own photo, absent parts left out),
  `middleware.test.ts` (`/t/…` not gated).
- **AC-004** — Live with a production build against a local worker on the FakeProvider: create
  from the result, open without a session, all files 200, bad link 404, reopen shows the open link,
  withdraw, link and file 404.
