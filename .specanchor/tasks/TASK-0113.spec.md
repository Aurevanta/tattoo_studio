# Task: Attach images to the idea, numbered, and let the architect read them (ADR-0039)

## 1. Problem / requested change

The owner wants to attach images in step 1, «¿Qué quieres tatuarte?», and to write the idea against
them, for example «como la imagen 1 pero con las rosas de la imagen 2». The consultation agent
should use the images to build the description that goes to the generator (INTENT, owner,
2026-10-15).

Product decisions taken by the owner on 2026-10-15 (INTENT):

| Question | Decision |
|---|---|
| How many images | up to 5 |
| Who uses them | Claude reads them, and they go to the image generator as references |
| Images with real people | refused, as today |
| Retention | as references: kept with the design; erased with the account's data |

## 2. Current behavior

- `IdeaStep` takes text only. `submitIdea` deletes any consultation and sends
  `{ action: 'orchestrate', userMessage }`. OBSERVED (`IdeaStep.tsx`, `app/page.tsx`).
- A client's own references are attached in step 3 through `POST /api/media` with
  `kind: 'reference'`, which runs the worker ingestion and adds a `user_supplied` reference to the
  session. OBSERVED (`api/media/route.ts`, `services/worker/app/studio.py::_ingest`).
- The architect is sent conversation text only; no client image reaches a language model.
  OBSERVED (`agents/architect.ts` header, `consultArchitect`).
- The ingestion refuses any real person for a reference, strips EXIF, encrypts, and keeps references
  for the design's lifetime; an account stores at most ten uploads. OBSERVED (`_ingest`,
  `safety/gate.py`).
- Removing a step-3 reference drops it from the session only; the stored image stays until the
  account's data is erased. OBSERVED (`api/consultation/route.ts`, `removeReference`).

## 3. Requirements

- **REQ-001 (web, step 1)**: `IdeaStep` offers «Adjuntar imágenes» (JPEG, PNG, WebP, ≤ 8 MB each,
  up to five). Each attached image is uploaded at once with `purpose: 'idea'` and shown as a
  thumbnail labelled «Imagen N», in attachment order, with a remove button. The step explains how
  to cite them and that removing one renumbers the rest. A refused image shows the gate's reason
  and is not added.
- **REQ-002 (BFF upload)**: `POST /api/media` with `purpose: 'idea'` forwards only the image with
  adult and consent to the worker's ingestion and does not change the consultation.
  `purpose: 'discard'` with an `assetId` asks the worker to delete that image and drops it from the
  consultation's references.
- **REQ-003 (BFF orchestrate)**: `action: 'orchestrate'` accepts `referenceIds`: at most five unique
  32-hex ids. For each, the BFF reads the worker's preview (owned by the account, else refused) and
  passes the orchestrator: the session references (`user_supplied`, label «Imagen N», source
  `/api/media?id=…`) and the architect images (the same, with the preview as a data URL).
- **REQ-004 (consultation)**: `handleUserInteraction` takes the architect images as an optional
  last argument. `consultArchitect` attaches them to the client's last turn. The Claude provider
  sends each image after a text block with its label, and the turn's text after them; the Astra
  provider does the same. The system prompt tells the architect to resolve references to numbered
  images into words in `subject.refined`, to describe only what is visible and never to name or
  imitate an image's author.
- **REQ-005 (worker)**: `GET /studio/media/{id}?preview=1` returns an owned reference as a JPEG
  whose longest side is at most 1568 px. `DELETE /studio/media/{id}` deletes an owned reference
  image with its cascade and its asset row, refuses (409) one any of the account's jobs uses, and
  answers 404 for anything not an owned reference.
- **REQ-006 (constraints)**: nothing above sends an image anywhere before the input gate passes;
  body photos are not accepted by either path; the image generator is reached only through the
  existing job path in `services/worker/generation`.

- **AC-001**: `api/media/route.test.ts`: `purpose: 'idea'` forwards only data, kind, adult and
  consent, and leaves the session untouched; `purpose: 'discard'` calls the worker's DELETE and
  drops the reference.
- **AC-002**: `api/consultation/route.test.ts`: `orchestrate` with two ids reads both previews and
  passes two numbered `user_supplied` references and two data-URL architect images; more than five
  ids, or a malformed id, is refused with 400 before any model is called.
- **AC-003**: consultation tests: the architect's last user turn carries the images; the Claude
  provider's request has, for that turn, «Imagen 1», image, «Imagen 2», image, then the text; the
  prompt names the rule.
- **AC-004**: worker tests: the preview is a JPEG within 1568 px; DELETE removes an unused reference
  (a later read is 404), refuses one used by a job (409), and refuses a body photo or another
  account's image (404).
- **AC-005**: `IdeaStep` test (static render): the control and what it accepts, numbered thumbnails
  in order with a remove button each and the citing hint, and no sixth image offered. Attaching and
  removing are exercised in the browser (AC-006).
- **AC-006**: in a browser, step 1 shows the control, numbered thumbnails and the hint.
- **AC-007**: lint, typecheck, tests (TS, worker, contracts) and the spec guard pass.
