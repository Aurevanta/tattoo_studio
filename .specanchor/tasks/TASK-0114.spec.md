# Task: Distant passers-by no longer get a reference refused (ADR-0040)

## 1. Problem / requested change

The owner attached a photograph of the Torres de Serranos to the idea. The studio refused it because
there is a person in it: two or three passers-by, a few pixels tall, by the gate. «No tiene
sentido» (OBSERVED, owner, 2026-10-16). Asked, the owner chose to refuse only identifiable people
(INTENT, owner, 2026-10-16).

## 2. Current behavior

- `CLASSIFY_PROMPT` asks for `contains_person`, which is true if any real person is visible
  anywhere, even partly or in the background, and true when unsure. `InputGate` refuses a
  reference with `CONTAINS_PERSON`. OBSERVED (`safety/openai_moderation.py`, `safety/gate.py`).
- The refusal says «La revisión ha visto una persona real en la imagen…». OBSERVED
  (`app/studio.py::REFUSED_UPLOAD`).
- Neither the architect's prompt nor the generator's prompts say anything about people in a
  reference. OBSERVED.

## 3. Requirements

- **REQ-001 (safety)**: The prompt asks for `identifiable_person`:
  - true for a person who is the subject, prominent, close or in the foreground; for a
    recognisable face; for a body part shown close up;
  - false for small, distant, incidental figures, and false when no person appears;
  - true when unsure.

  `ModerationOutcome.identifiable_person` replaces `contains_person`. A verdict under the old key is
  malformed, so it is refused. `GATE_VERSION` is `input-gate-2`. Explicit content and the own-body
  exception are unchanged.
- **REQ-002 (generation, consultation)**: The reference analysis ignores incidental people and never
  describes a real person. A referenced artwork prompt leaves them out. Architect rule 12 leaves
  them out; a figure the client asks for is generic.
- **REQ-003 (platform, web)**: The refusal names a person who can be recognised and suggests
  cropping. Step 1's hint matches.
