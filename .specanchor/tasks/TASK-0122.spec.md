# Task: `pnpm lint` checks this project only, not nested worktrees or local output

## Problem

The audit of 2026-10-16 (owner's list, item 7) and TASK-0113 ev-001 record that plain `pnpm lint`
fails on the owner's machine on files outside the tracked tree: a Claude Code worktree under
`.claude/worktrees/` (a whole second checkout, git-excluded through `.git/info/exclude`) and
`services/worker/.artifacts/` (git-ignored). Tasks since then ran `eslint . --ignore-pattern
'.claude/**'` by hand, so the project's own quality command was not the one being run.

Cause: ESLint reads neither `.gitignore` nor `.git/info/exclude`; its ignore list covered
`.specanchor/**` only at the root, so a worktree's `.specanchor/evidence/*.mjs` was linted. Prettier
3 reads `.gitignore` but not `.git/info/exclude`, so it formatted-checked the worktree's schemas.

## Change

- `eslint.config.mjs`: ignore `.claude/worktrees/**`, `**/.uploads/**`, `**/.artifacts/**`.
- `.prettierignore`: the same three.

## Acceptance

- **AC-001**: with a real nested worktree (`git worktree add .claude/worktrees/repro-lint`, excluded
  in `.git/info/exclude`) holding a file with lint errors, and a lint error in
  `services/worker/.artifacts/dump.js`, `pnpm lint` exits 0. Before the change it failed.
- **AC-002**: a lint error in a tracked source file (`apps/web/src/zz-canary.ts`) still makes
  `pnpm lint` exit 1.

## Evidence

- **ev-001** — 2026-10-16. Status: VERIFIED by execution (cloud session, clean clone at 2d32173).
  Before: `pnpm lint` reported 30 errors, all under `.claude/worktrees/repro-lint/` (`probes.cjs`,
  `live-acceptance.mjs`, `stale.ts`), plus `services/worker/.artifacts/dump.js` once it held an
  error; `prettier --check` warned on 84 files in the worktree. After: `pnpm lint` exit 0 with both
  present (AC-001); with the canary, exit 1 (AC-002). Worktree, artefact, canary and exclude line
  removed afterwards.
