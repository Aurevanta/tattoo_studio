# Task: The 3D views draw only when something changes and can be seen

## Problem

Owner's audit list (2026-10-16, item 6): «Optimizar los visores 3D. Detener el renderizado cuando no
hay cambios o el visor no está visible, reduciendo consumo de batería y GPU.» `body-scene.ts` and
`limb-scene.ts` ran a `requestAnimationFrame` loop that called `controls.update()` and rendered
every frame for as long as a view was mounted (OBSERVED). Since TASK-0118 the 3D view opens with
every result, so a phone drew the reference body at the display's rate while the client read the
notices, scrolled past it, or left it still.

## Change

- `lib/render-on-demand.ts`: `onDemand(draw, clock)` draws a frame when invalidated and keeps
  drawing only while `draw` reports the picture still moving (OrbitControls' damping); nothing
  while invisible, one frame on becoming visible. `watchVisibility` combines an
  IntersectionObserver on the view's container with the page's `visibilityState`.
- Both scenes: the loop is replaced; the orbit's `change` event, placement, side, tone, view and
  resize invalidate; dispose stops the clock and the observers.

## Acceptance

- **AC-001**: `render-on-demand.test.ts` — no frame while nothing changes; changes before a frame
  draw once; a settling picture draws until it stops; nothing off screen or hidden; one frame when
  seen again; nothing after dispose.
- **AC-002**: in Chromium, with both viewers on one page (body on screen, limb 4000 px below),
  counting WebGL `clear` calls per viewer: idle 0; a drag draws, then stops after the damping
  settles; the off-screen limb draws nothing until scrolled into view; a hidden page draws nothing,
  and a drag made while hidden is drawn once visible.
- **AC-003**: typecheck, eslint, prettier, vitest.
