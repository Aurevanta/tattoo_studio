# Task: The specs say what the stencil really is — native line art, or approximate colour contours

## 1. Current behaviour (OBSERVED, a6cf32e)

- `trace_native_lineart` traces a dedicated line-art pass (ADR-0003). `trace_colour_artwork`
  traces Canny edges of the flat colour or shaded artwork (TASK-0019/REQ-011): edge detection of
  the shaded render, which ADR-0003, STENCIL-INV-001 and CLAUDE.md's hard constraint exclude.
- The result (`stencilReview.method: colour_contours`), the result view and the tattooer's link say
  «contornos aproximados» (TASK-0086). The printed PDF and the SVG did not: a tattooer holding the
  sheet could not tell.
- `stencil.spec.md` listed interfaces that were never built (`render_linework`, `trace_to_vector`,
  `export_stencil`).

## 2. Desired behaviour (INTENT, owner's audit list 2026-10-16, item 8)

«Alinear las especificaciones con el stencil real. Diferenciar claramente line-art nativo y
contornos aproximados derivados de diseños a color.» Decided in ADR-0044.

- **REQ-001**: the specs, ADR-0003 and CLAUDE.md name two regimes and their invariants.
- **REQ-002**: an approximate stencil says so on every printed page (first page, A4 pieces, sleeve
  panels) and in its SVG; a line-art stencil does not; the mark survives rescaling and unrolling.

## 3. Acceptance criteria

- **AC-001** (REQ-001): `stencil.spec.md` STENCIL-INV-001a/b, real public interfaces, statement
  evidence; ADR-0003 amended by ADR-0044; CLAUDE.md hard constraint; spec index.
- **AC-002** (REQ-002): `stencil/tests/test_approximate.py` — no note on line art; on a 250 × 380 mm
  colour stencil both lines on `1 + columns × rows` pages, mirrored too, and the SVG `<desc>`;
  `rescale`, `rescale_axes`, `unroll` + `panels` keep it.
- **AC-003** (REQ-002): rendered pages (`pdftoppm`): the note is legible on the narrowest page
  (80 mm), clear of the corner marks on an A4 piece, and above a sleeve panel's title.
- **AC-004**: worker ruff, format, mypy, pytest.
