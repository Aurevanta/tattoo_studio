# Task: Changing a stored design does not need the browser's consultation

## Problem

Reported by the owner (INTENT): changing the last design shows «Tu sesión ha caducado. Vuelve a
entrar.»; signing in again shows it again.

Cause (OBSERVED in `apps/web/src/app/api/generate/route.ts` and `lib/studio-server.ts`; reproduced
by the new test, 401 before the change): `POST /api/generate` asked for the browser's consultation
(`session(request, false, …)`) before handling an `edit`. The consultation expires 24 hours after
its last change and does not exist on a second device; its absence answers 401, which the client
words as an expired sign-in (`messageForResponse`). Signing in again creates no consultation, so the
message repeats. TASK-0046 already moved stored work to the account and made reading it independent
of the consultation; the change request was left behind.

## Change

- `POST /api/generate` with `edit`: uses the browser's consultation when it has one (its job is
  remembered there and the busy lock still applies) and otherwise forwards the edit for the
  account without starting a consultation or setting the `inkcraft` cookie. A new generation still
  requires the consultation and its accepted brief.
- `route.test.ts`: an edit with no consultation in the browser is accepted (202), forwards only
  parent, instruction and idempotency key, and sets no consultation cookie.

## Acceptance
